Grounding Context

Codebase context. FastAPI + Next.js App Router; Local Studio dark-first DESIGN.md. F-011 backend complete (wiki.py, routes, 6 pytest; AC-001–009 pass). AC-010 deferred — no frontend/src/features/wiki/, no /wiki route. Nav today: Chat, Library, Graph, Logs. Mirror documents/ (ceFetch + list/detail + admin gate). ChatShell tab wiki is F-012 composer-ref discovery, not curation.

Constraints (user-named). Slice 4 plan: member list/create/edit/submit; admin review publish/reject; read published; touch features/wiki/ + AC-010. F-011: manual-only; tables not cards; no durable browser drafts; no AI/SSE/attachments. Smart Composer lesson: do not port PGlite, providers, Apply, vault RAG. API-001 P11 already contracts all routes/DTOs/state machine.

Past learnings. Thin docs/solutions/: typed DTO polling, safe DTOs, no browser-owned lifecycle. Avoid login-shell UI without server truth.

External context. Keep admin triage separate from published browse. Frase/PR-style: row → detail → few actions → lock after decision. Rejection-reason feedback is high value / low cost. State machine is the product.

1 · TOP PICK

Contract-first wiki/api.ts + AC-010 Playwright harness

Conf 94% Complexity Medium axis: typed-wrappers-ac010
Description
Before any page chrome, ship frontend/src/features/wiki/api.ts mirroring documents/api.ts: typed DTOs from API-001, ceFetch cookie session only. Add Playwright helpers that drive draft→submit→publish→reject→browse via API (not UI) for setup, then one thin E2E path that proves the three Slice 4 flows. Update F-011 acceptance AC-010 + T-070/T-080. Bundle or explicitly defer T-060 OpenAPI snapshot.
Basis
direct: AC-010 deferred; T-070/T-080 open; documents/api.ts pattern; AGENTS.md typed wrappers + no browser token persistence; DoD requires Playwright/visual + safety scan.
Rationale
Without typed wrappers, every component invents URLs and drifts from the contract. The harness makes AC-010 a forcing function instead of a screenshot tour — and amortizes every later wiki E2E (F-012 refs included).
Downsides
Feels like “no UI yet” for a day; OpenAPI snapshot still open if not bundled.
2

Dedicated /wiki workspace — Library sibling, not ChatShell

Conf 90% Complexity Medium axis: shell-placement
Description
Add a Wiki nav item and app/wiki/ routes. Build features/wiki/ as a peer of documents/: left rail + list canvas + right detail. Do not extend ChatShell’s wiki tab (that stays F-012 ref discovery). No Smart Composer chrome, ref chips, or Apply UX.
Basis
direct: Slice 4 targets features/wiki/; ChatShell wiki tab is F-012 discovery; F-011 ux.md left-rail|canvas|detail; SC lesson forbids runtime port; NAV_ITEMS currently has no Wiki.
Rationale
Curation is lifecycle work (file → review → catalog), not chat. A dedicated rail mode prevents juniors from wiring wiki writes into the composer and keeps Local Studio shell grammar intact.
Downsides
One more top-level nav item; must teach that Chat “Wiki” ≠ Wiki workspace.
3

Three separate surfaces — never blend browse with triage

Conf 91% Complexity Medium axis: published-browse
Description
Ship three clear entry points (tabs or routes under /wiki): Published (GET pages), My contributions (owner drafts/submitted), Review (admin-only, GET admin contributions). Do not put publish/reject on the published catalog, and do not show other users’ drafts in browse.
Basis
direct: API-001 separates /wiki/pages, /wiki/contributions, /admin/wiki/contributions; members 404 on non-published; external grounding: open stacks vs closed stacks / Frase queue separation. Verifier refuted “one blended filter home.”
Rationale
Blending triage into browse recreates Notion’s draft-leak problem and hides the “only published serves knowledge” guarantee. Separate surfaces map 1:1 to contracts and role gates.
Downsides
Slightly more routing than a single mega-table; needs clear empty states per surface.
4

Admin Frase/PR triage — row → detail → publish/reject → lock

Conf 88% Complexity Low axis: admin-review
Description
Admin Review is a table: click row → right detail (read-only title/body) → Publish | Reject. Reject exposes optional reviewerNote (API-optional — prompt strongly on deny, do not hard-block empty). After success, disable actions from returned DTO state (optimistic lock OK). Mirror DocumentsPage admin gate / extract shared AdminGate if cheap.
Basis
direct: API-001 publish/reject + idempotent publish; ux.md tables + admin-only actions; external: Frase/PR merge-queue lock-after-decision. Softened from “UI-required note” after verifier (API allows empty).
Rationale
Closes the admin half of Slice 4 with almost no chrome. Rejection note (when present) is the cheapest feedback loop that improves re-submits.
Downsides
No diff viewer (correctly out of scope); concurrent admins still rely on server idempotency.
5

Server-status-driven field lock

Conf 82% Complexity Low axis: member-draft-submit
Description
Member contribution form derives readOnly from API state: draft editable; submitted/published/rejected/blocked not. Show StatusPill from existing UI kit (not invent data-status attributes). Optional lightweight confirm on Submit (“locks until review”) — nice-to-have, not required by contract.
Basis
direct: F-011 states draft editable / submitted owner read-only; ux.md API truth; copy-desk handoff analogy. Verifier: drop custom data-status convention — use StatusPill/testIds.
Rationale
One rule prevents client/server editability drift and teaches the state machine without CMS jargon.
Downsides
Submit confirm adds a click; skip if it delays AC-010.
6

Stable /wiki/pages/{id} URLs for F-012

Conf 90% Complexity Low axis: published-browse
Description
Published detail route matches API path shape: /wiki/pages/[pageId]. Soft-handle member 404 for needs_review/archived (“not published”) without crashing the shell. List uses summaries; detail GET loads body (do not invent body from list).
Basis
direct: API-001 page detail returns body; list is summaries only (verifier refuted optimistic-from-list); F-012 may deep-link published wiki refs later.
Rationale
One URL decision removes a mapping layer for F-012 and Playwright navigation helpers.
Downsides
None material for Slice 4.
7

Defer evidence-ref picker unless trivial

Conf 72% Complexity Low axis: member-draft-submit
Description
Ship create/edit as title + body first. Omit evidence-ref multi-select until a later micro-slice unless wiring is trivial (empty array always). Server already allows omitted/empty evidenceRefIds. Document the deferral in acceptance so F-011 ux “selected evidence refs” is an explicit follow-up, not silent drift.
Basis
direct: API-001 optional evidence refs; Slice 4 skip list (SC polish/attachments); verifier marked weak vs ux.md layout — keep only with explicit acceptance note.
Rationale
Evidence pickers couple to turn evidence discovery and can block the whole Slice 4 ship. Title+body closes the governed loop; refs can attach later without changing submit/publish.
Downsides
Partial F-011 ux surface; must not pretend evidence UI shipped.

# Spec Readiness Checklist

A feature is ready for technical planning only when:

- [ ] Feature ID, title, owner, and status exist.
- [ ] User/business outcome is explicit.
- [ ] Scope and non-goals are explicit.
- [ ] Roles/permissions are defined.
- [ ] Main and exception behaviour flows are defined.
- [ ] Business rules have source/owner.
- [ ] Data writes and state transitions are explicit.
- [ ] Affected API/event/data/AI contracts are linked.
- [ ] Security, privacy, audit, and retention impact is stated.
- [ ] NFRs are measurable or explicitly not applicable.
- [ ] Acceptance criteria are observable and testable.
- [ ] Open decisions are visible with owner.
- [ ] Dependencies and risks are listed.
- [ ] Feature register is updated.
